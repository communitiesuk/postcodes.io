Postcodes.io can be self-hosted with two Docker images: the API container (`idealpostcodes/postcodes.io`) and a pre-seeded PostgreSQL/PostGIS database container (`idealpostcodes/postcodes.io.db`).

The database image bundles a pre-built `pg_dump` produced by our upstream data pipeline — there is no in-container ingest step. The API container is stateless and connects to whatever Postgres you point it at.

### Requirements

- A local clone of [postcodes.io](https://github.com/ideal-postcodes/postcodes.io)
- [Docker](https://www.docker.com/) (Compose v2 ships with modern Docker installations)

### Quickstart

```bash
docker-compose up -d
```

This brings up the database and API containers and networks them. The HTTP service is exposed on port `8000`.

### Application container

`idealpostcodes/postcodes.io` provides the HTTP interface. It is stateless and expects a populated PostgreSQL/PostGIS instance reachable over the network.

```bash
docker run -d -p 8000:8000 idealpostcodes/postcodes.io
```

Configuration is environment-variable-driven.

#### HTTP

| Variable               | Purpose                                                                                                                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `HOST`                 | Host/interface to bind to (defaults to `0.0.0.0`).                                                                                                                                                                                                                                         |
| `PORT`                 | HTTP port the API listens on (defaults to `8000`).                                                                                                                                                                                                                                         |
| `URL_PREFIX`           | Prefix prepended to every route (e.g. `/v1`). Empty by default.                                                                                                                                                                                                                            |
| `HTTP_HEADERS`         | JSON object of headers to attach to every response, e.g. `'{"X-Foo":"bar"}'`. Applied after the built-in [Helmet](https://helmetjs.github.io/) security headers, so it can override them.                                                                                                  |
| `CORS_ALLOWED_ORIGINS` | Comma-separated list of origins allowed by CORS, e.g. `https://foo.example.com,https://bar.example.com`. Unset by default: the API is deliberately public and unauthenticated, so any origin (`*`) may call it. Set this only if your deployment should serve known consumers exclusively. |

#### Database

| Variable                      | Purpose                                                                                                                                                                                                    |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POSTGRES_USER`               | Database username.                                                                                                                                                                                         |
| `POSTGRES_PASSWORD`           | Database password.                                                                                                                                                                                         |
| `POSTGRES_DATABASE`           | Database name.                                                                                                                                                                                             |
| `POSTGRES_HOST`               | Database host.                                                                                                                                                                                             |
| `POSTGRES_PORT`               | Database port.                                                                                                                                                                                             |
| `POSTGRES_POOL_MAX`           | Maximum connections in the pool per API instance. Default `10`. Size it against your database's connection limit divided by the number of API instances.                                                   |
| `POSTGRES_STATEMENT_TIMEOUT`  | Server-side `statement_timeout` in milliseconds applied to every pooled connection, so a slow query is cancelled by Postgres instead of tying up the pool. Default `5000`; `0` disables.                   |
| `POSTGRES_CONNECTION_TIMEOUT` | How long in milliseconds a request may wait for a database connection before the API returns `503`: queueing behind other requests when the pool is full, and establishing a new connection (TLS, authentication and, on Azure, the managed identity token fetch). Default `5000`; `0` waits indefinitely. |

#### Logging & metrics

| Variable              | Purpose                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------- |
| `LOG_NAME`            | Name attached to JSON log output.                                                         |
| `LOG_DESTINATION`     | `stdout`, `perf` (high-throughput stdout via `pino.extreme`), or a file path.             |
| `PROMETHEUS_USERNAME` | Enables a basic-auth-protected `/metrics` endpoint when both `PROMETHEUS_*` vars are set. |
| `PROMETHEUS_PASSWORD` | Password for the `/metrics` endpoint.                                                     |

#### Request limits

All limit variables are integers. Defaults are tuned for a single-node deployment; raise them only after benchmarking your hardware. The API clamps any incoming `limit` / `radius` query parameter to the `*_MAX` ceiling — it does not reject the request.

| Variable                         | Endpoint                             | Default | Notes                            |
| -------------------------------- | ------------------------------------ | ------- | -------------------------------- |
| `NEAREST_LIMIT_DEFAULT`          | `GET /postcodes?lon=&lat=`           | `10`    | Applied when `limit` is omitted. |
| `NEAREST_LIMIT_MAX`              | `GET /postcodes?lon=&lat=`           | `100`   | Hard cap on `limit`.             |
| `NEAREST_RADIUS_DEFAULT`         | `GET /postcodes?lon=&lat=`           | `100`   | Metres.                          |
| `NEAREST_RADIUS_MAX`             | `GET /postcodes?lon=&lat=`           | `2000`  | Metres.                          |
| `SEARCH_LIMIT_DEFAULT`           | `GET /postcodes?q=`                  | `10`    |                                  |
| `SEARCH_LIMIT_MAX`               | `GET /postcodes?q=`                  | `100`   |                                  |
| `BULKLOOKUPS_POSTCODES_MAX`      | `POST /postcodes` (`postcodes[]`)    | `100`   | Array length cap.                |
| `BULKGEOCODE_GEOLOCATIONS_MAX`   | `POST /postcodes` (`geolocations[]`) | `100`   | Array length cap.                |
| `NEARESTOUTCODES_LIMIT_DEFAULT`  | `GET /outcodes?lon=&lat=`            | `10`    |                                  |
| `NEARESTOUTCODES_LIMIT_MAX`      | `GET /outcodes?lon=&lat=`            | `100`   |                                  |
| `NEARESTOUTCODES_RADIUS_DEFAULT` | `GET /outcodes?lon=&lat=`            | `5000`  | Metres.                          |
| `NEARESTOUTCODES_RADIUS_MAX`     | `GET /outcodes?lon=&lat=`            | `25000` | Metres.                          |
| `PLACESSEARCH_LIMIT_DEFAULT`     | `GET /places?q=`                     | `10`    |                                  |
| `PLACESSEARCH_LIMIT_MAX`         | `GET /places?q=`                     | `100`   |                                  |

#### Rate limiting

All API routes are rate limited per client IP. Health checks (`GET /ping`, `GET /ready`) and the static documentation site are exempt. The bulk endpoint (`POST /postcodes`) has its own, stricter allowance, counted separately from the general limit. Limited requests receive `429` with a JSON error body, and every limited route returns both `RateLimit-*` (IETF draft-6) and legacy `X-RateLimit-*` headers.

| Variable                    | Default | Purpose                                                             |
| --------------------------- | ------- | ------------------------------------------------------------------- |
| `RATE_LIMIT_ENABLED`        | `true`  | Set to `false` to disable application-level rate limiting.          |
| `RATE_LIMIT_WINDOW_MS`      | `60000` | General window size in milliseconds.                                |
| `RATE_LIMIT_MAX`            | `300`   | Requests allowed per IP per window on `GET` API routes.             |
| `RATE_LIMIT_BULK_WINDOW_MS` | `60000` | Window size for `POST /postcodes` (bulk lookup / bulk geocode).     |
| `RATE_LIMIT_BULK_MAX`       | `30`    | Bulk requests allowed per IP per window.                            |
| `TRUST_PROXY`               | unset   | Express [`trust proxy`](https://expressjs.com/en/guide/behind-proxies.html) setting. Unset trusts all proxies (`req.ip` is the leftmost `X-Forwarded-For` entry, which clients can spoof). Behind a known chain set the hop count (e.g. `1` for a single gateway/load balancer) so rate limits key on the true client IP. Also accepts `false`, a preset (e.g. `loopback`) or a comma-separated IP/CIDR list. |

Counters are held in process memory: with several instances behind a load balancer the effective ceiling is `max × instances`, and counters reset on restart. Use a gateway/WAF rate limit for a hard multi-instance guarantee.

### Database container

`idealpostcodes/postcodes.io.db` is built on top of the official `postgis/postgis` image and ships a pre-loaded `pg_dump` of the latest ONSPD / OS Open Names / Scottish Postcode Directory data, denormalised into the `public` schema (`public.postcodes`, `public.places`, `public.scottish_postcodes`, `public.outcodes`). The image is rebuilt and re-tagged each time the upstream dump is refreshed; see the [Changelog](https://github.com/ideal-postcodes/postcodes.io/blob/master/CHANGELOG.md) for dataset cadence.

:::info
On first start the container enables PostGIS and restores the dump. Restoration takes 1-3 minutes depending on hardware. Subsequent starts skip the restore.
:::

```bash
docker run -p 5432:5432 \
  -e POSTGRES_USER=postcodesio \
  -e POSTGRES_DB=postcodesiodb \
  -e POSTGRES_PASSWORD=password \
  idealpostcodes/postcodes.io.db
```

This image inherits the upstream PostgreSQL configuration surface — see the [postgres image documentation](https://hub.docker.com/_/postgres/) for the full set of environment variables.

### Running the API against your own database

If you already have a Postgres instance loaded with the dump (e.g. by piping the raw `pg_dump` SQL into your own DB), point the API at it via the `POSTGRES_*` variables above. The API is read-only at runtime — no migrations, no support tables to rebuild.
